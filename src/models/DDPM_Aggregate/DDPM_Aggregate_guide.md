## 1. 全体像 — 何を解く問題か

### 1.1 やりたいこと

**入力**: 米国 ATUS 2024 の個票（1 人 1 日の 96 スロット活動スケジュール、属性ラベル付き）と、
日本の社会生活基本調査（社基調）の**公表集計表だけ**。日本の個票は手元にない。

**出力**: 「性 × 年齢 × 就業」の 28 群それぞれについて、
**日本の集計値に合致し、かつ 1 日の系列として自然な**個票スケジュールの集合。

米国側は個票と属性ラベルが揃っているので、通常の条件付き学習ができる。
日本側は個票がなく公表集計しかないので、そこだけを集計教師で埋める。
これが米国 → 日本のドメイン転移（[[concepts/domain-adaptation]]）を
集計統計だけで行うという問題設定（[[concepts/aggregate-supervision]]）である。

### 1.2 2 段構成（Stage1 / Stage2）

| | 担当ファイル | 何を学ぶ / 決めるか | 教師 |
|---|---|---|---|
| **Stage 1** | `model.py` | 「群 d らしい 1 日のスケジュール」の生成器（条件付き DDPM） | 米国 ATUS の**個票** |
| **Stage 2** | `japan_match_experiment.py` | 生成済み日記 1 本 1 本の**重み**（生成器は凍結） | 日本社基調の**公表集計** |

Stage 2 の一文要約: **「モデルを直さず、どの日記をどれだけ重く数えるかだけを直す」**。

```
ATUS個票 3,736日 ──Stage1(学習)──▶ 条件付きDDPM ──サンプリング──▶ 群別プール (28群 × 2,000本)
                                       (凍結)                              │
社基調 公表2表 ────────────────────────────────────────指数傾け──────────▶ 重み w (28, 2000)
                                                                            │
                                                     群別期待行動者率 μ̂ ◀───┘ → 28群ホールドアウト評価
```

### 1.3 なぜ CVAE ではなく DDPM なのか

先行実装 `CVAE_Aggregate` は decoder を $p(x \mid z) = \prod_t p(x_t \mid z)$ と
**スロットごとに分解**する。この条件付き独立の仮定により、$z$ で説明しきれない残差が
時間的に無相関なノイズとして現れ、**個票が激しく断片化**した（`model.py` 冒頭の docstring）:

| 指標（ATUS 平日・共通 12 分類） | 実データ | CVAE 生成 |
|---|---|---|
| 1 日の平均活動切替回数 | 12.64 | **48.1**（3.8 倍） |

ハイパーパラメータの掃引では改善しなかったため、系列構造を保てる DDPM に生成器を差し替えた
（判断の経緯は `model.py` と `japan_match_experiment.py` の docstring。
この構成は `docs/proposals.md` 提案③「LLM 提案分布 × 指数傾け」の生成器側に相当する）。

**代償**: 拡散の逆過程には勾配が通らないため、CVAE 版 Stage2 の
「$\hat\mu$ への勾配降下」が使えない（→ [8.1](#81-なぜ勾配法が使えないのか)）。
その代わりに Stage2 は**凸最適化（指数傾け）**になり、局所解の心配がなくなる。

## 2. 拡散モデルの基礎

本章は拡散モデル自体の説明である。既に知っている場合は
[3 章](#3-離散スケジュールを連続拡散に載せる)へ進んでよい。
対応するコードは `model.py` の `class Diffusion`（L347-434）。

### 2.1 発想 — 「壊す過程」を逆再生する

拡散モデルは 2 つの過程からできている。

- **forward 過程（拡散, 固定・学習しない）**: 本物のデータ $x_0$ に少しずつガウスノイズを足し、
  $T = 1000$ 段かけて純粋なノイズ $x_T \sim N(0, I)$ にする
- **reverse 過程（生成, 学習する）**: 純粋なノイズから出発し、
  「少しノイズを取り除く」を 1000 回繰り返して $x_0$ に戻す

ポイントは、**forward が固定なので「正解」が自分で作れる**こと。
任意の本物データにノイズを好きなだけ足せるので、
「ノイズが乗ったデータ → 乗せたノイズ」という教師ありデータが無限に作れる。
拡散モデルの学習が GAN より安定している理由はここにある。

### 2.2 forward 過程は 1 発で書ける

1 ステップの定義は $x_t = \sqrt{1-\beta_t}\, x_{t-1} + \sqrt{\beta_t}\,\epsilon$
（$\beta_t$ は「そのステップでどれだけ壊すか」）。
ガウス分布の再生性により、これを $t$ 回合成した結果も 1 発の式で書ける:

$$\alpha_t = 1 - \beta_t,\qquad \bar\alpha_t = \prod_{s \le t}\alpha_s$$

$$\boxed{\;x_t = \sqrt{\bar\alpha_t}\,x_0 + \sqrt{1-\bar\alpha_t}\,\epsilon,\qquad \epsilon \sim N(0,I)\;}$$

これがコードの `q_sample`（L364-367）そのもの。
**中間の $x_1, \dots, x_{t-1}$ を作らずに、任意の $t$ の状態へ一発で飛べる**ので、
学習ではランダムな $t$ を 1 個引くだけで済む。

$\bar\alpha_t$ は「元データがどれだけ残っているか」を表す信号強度である。
本コードの設定（`BETA_START=1e-4`, `BETA_END=0.02`, `T_STEPS=1000` の linear schedule）での実測値:

| $t$（0 始まり） | 0 | 99 | 499 | 799 | 999 |
|---|---|---|---|---|---|
| $\sqrt{\bar\alpha_t}$（信号の残り） | 0.9999 | 0.9471 | 0.2803 | 0.0391 | 0.0064 |
| $\sqrt{1-\bar\alpha_t}$（ノイズの量） | 0.0100 | 0.3209 | 0.9599 | 0.9992 | 1.0000 |

$t=999$ では信号がほぼ消えて $x_T$ は標準正規分布と見分けがつかない。
これが「ノイズから出発してよい」根拠になる。

### 2.3 学習 — ε を当てるだけ

reverse 過程を直接学ぶ代わりに、DDPM は**「乗せたノイズ $\epsilon$ を当てる」回帰**を学ぶ。
損失は驚くほど単純（`Diffusion.loss`, L369-377）:

$$\mathcal{L} = \mathbb{E}_{x_0,\;t \sim U\{0,999\},\;\epsilon \sim N(0,I)}
\left[\;\bigl\|\;\epsilon - \epsilon_\theta(x_t, t, c)\;\bigr\|^2\;\right]$$

```python
x0 = sched_to_x0(sched)                                   # 本物データ
t = torch.randint(0, T_STEPS, (x0.size(0),))              # ★各サンプルに t を独立ランダムに割り当て
eps = torch.randn_like(x0)                                # 正解ノイズ
x_t = self.q_sample(x0, t, eps)                           # 一発で t 段ノイズを乗せる
eps_hat = model(x_t, t, cond_idx, drop_mask)              # ノイズを予測
return F.mse_loss(eps_hat, eps)                           # ただの MSE
```

理論的には、この単純な MSE は変分下界（ELBO）の各項を重み付けし直したものにあたる
（Ho et al. 2020 の $L_\text{simple}$）。
**係数を捨てて等重みにしたことで、実装が単純になり学習も安定した**というのが DDPM の要点である。

$\epsilon$ が当たれば $x_0$ も式で復元できる（$x_0 = (x_t - \sqrt{1-\bar\alpha_t}\,\hat\epsilon)/\sqrt{\bar\alpha_t}$）ので、
「ノイズを予測する」と「元データを予測する」は等価な言い換えである。
$\epsilon$ 予測が好まれる理由は、予測対象のスケールが $t$ に依らず一定（分散 1）であり、
損失の大きさが $t$ の間で揃うことにある。

### 2.4 reverse 過程（ancestral sampling）

学習した $\epsilon_\theta$ を使って、$x_T$ から 1 ステップずつ戻る（`Diffusion.sample`, L388-402）:

```python
x = torch.randn(m, IN_CH, NUM_SLOTS)              # x_T ~ N(0, I)
for ti in reversed(range(T_STEPS)):               # 999, 998, ..., 0
    eps_hat = self._eps(model, x, ti, cond_idx, guidance_scale)
    x0_hat  = (x - self.sqrt_1m_acp[ti] * eps_hat) / self.sqrt_acp[ti]   # ε から x0 を復元
    x0_hat.clamp_(-1.0, 1.0)                                            # ★安定化（後述）
    mean = self.post_coef_x0[ti] * x0_hat + self.post_coef_xt[ti] * x    # 後方平均
    x = mean + self.post_var[ti].sqrt() * torch.randn_like(x) if ti > 0 else mean
return x.argmax(dim=1)                             # 連続値 → 活動ラベル
```

3 つの係数は $q(x_{t-1} \mid x_t, x_0)$ という**厳密に計算できる**分布の平均と分散である
（`Diffusion.__init__`, L360-362）:

$$\tilde\mu_t = \underbrace{\frac{\beta_t\sqrt{\bar\alpha_{t-1}}}{1-\bar\alpha_t}}_{\texttt{post\_coef\_x0}} \hat{x}_0
\;+\; \underbrace{\frac{(1-\bar\alpha_{t-1})\sqrt{\alpha_t}}{1-\bar\alpha_t}}_{\texttt{post\_coef\_xt}} x_t,
\qquad
\tilde\beta_t = \underbrace{\frac{\beta_t(1-\bar\alpha_{t-1})}{1-\bar\alpha_t}}_{\texttt{post\_var}}$$

**読み方**: $x_0$ が分かっていれば 1 ステップ戻る分布は厳密に書ける。
そこで**モデルが推定した $\hat{x}_0$ を本物の代わりに差し込む**。これが reverse 過程の中身である。

実装の細部で意味があるもの:

- **`x0_hat.clamp_(-1, 1)`**: データ表現が $\{-1,+1\}$（→ [3 章](#3-離散スケジュールを連続拡散に載せる)）なので、
  復元値をその範囲に押し込む。$t$ が大きいと $\sqrt{\bar\alpha_t} \approx 0.006$ で割るため、
  $\hat\epsilon$ のわずかな誤差が $\hat{x}_0$ では 150 倍に増幅される。clamp はその増幅を抑える安全装置である
- **最終ステップ（`ti == 0`）でノイズを足さない**: 出力は分布ではなく 1 点が欲しいので平均を返す
- **`argmax(dim=1)`**: チャネル軸（活動 12 分類）で最大の成分を選び、離散ラベルに戻す

### 2.5 CVAE / GAN との違い（1 行ずつ）

| | 生成 1 回のコスト | 学習の安定性 | 系列構造 |
|---|---|---|---|
| CVAE | decode 1 回 | 安定 | スロット独立に分解すると壊れる（本リポジトリの実測で 3.8 倍の断片化） |
| GAN | generator 1 回 | 不安定（モード崩壊） | — |
| **DDPM** | **1000 ステップ**（遅い） | 安定 | 毎ステップ全スロットを同時に見るため保たれる |

「表現力と引き換えに生成が遅い」というトレードオフは [[concepts/diffusion-model]] の
横断的知見どおりであり、本コードでもプール生成のコストとしてそのまま現れる
（→ [10 章](#10-実行手順と計算コスト)）。

## 3. 離散スケジュールを連続拡散に載せる

### 3.1 何が問題か

拡散の forward はガウスノイズを**足す**操作なので、入力は連続値でなければならない。
一方スケジュールは「スロット $t$ の活動は SLEEP」という**カテゴリ**である。
カテゴリにノイズは足せない。

### 3.2 本コードの解 — one-hot を $\pm 1$ にして直接拡散する

`sched_to_x0`（L232-235）の実装は実質 2 行である:

```python
onehot = F.one_hot(sched, NUM_ACT).float().permute(0, 2, 1)   # (B,96) → (B,12,96)
return 2.0 * onehot - 1.0                                     # {0,1} → {-1,+1}
```

- 形状 `(B, 12, 96)` = （バッチ, 活動 12 分類, 時刻 96 スロット）。**活動をチャネル軸に置く**
- 値域を $\{0,1\}$ ではなく $\{-1,+1\}$ にするのは、
  値の振れ幅を足すノイズ（分散 1 のガウス）と同じ桁に揃えるため
  （画像を $[-1,1]$ に正規化するのと同じ動機）
- 戻すときは `argmax(dim=1)`

これは Tang et al. 2025（[[papers/tang-2025-diffusion-popsynth]]）の
「離散 one-hot → 連続表現 → Gaussian DDPM → argmax デコード」の枠組みである。
[[queries/ddpm-vs-other-diffusion]] のとおり、
カテゴリを直接扱う離散拡散（D3PM 等）ではなく、連続拡散に載せる流派を採っている。

活動数が 12（共通分類、[[concepts/activity-schema-alignment]]）と少ないため、
学習可能な埋め込み層を挟まなくても、入力 Conv1d が実質の埋め込みとして働く
（`model.py` 冒頭の設計方針、および `DDPM/model.py` の docstring）。

### 3.3 この表現の帰結（重要）

- 生成された $x$ は**連続値**で、各スロットは 12 次元ベクトル。
  「どの活動か」は argmax で読むだけなので、$x$ の絶対値の大小に意味はない
- したがって、モデルが「SLEEP と MEALS の中間」のようなぼやけた出力を出すと、
  **argmax がスロットごとにちらついて断片化する**。
  これが [7 章](#7-サンプリング--ancestral-と-ddim)で DDIM を使えない理由に直結する
- 96 スロットには必ず何かのラベルが付く（空きスロットはない）。
  比較不能な活動 OTHER_X も**生成はされる**。除外は Stage2 の制約側と評価側で行う
  （`NUM_ACT` の定義コメント L74）

## 4. 条件付け（28群）と classifier-free guidance

### 4.1 群の定義

$$d = g \cdot (N_A N_E) + a \cdot N_E + e \qquad (N_G, N_A, N_E) = (2, 7, 2),\quad D = 28$$

- $g$: 性別（0 = 男, 1 = 女）
- $a$: 年齢 7 区分（15 歳起点 10 歳刻み、`np.clip((age-15)//10, 0, 6)`）
- $e$: 就業（0 = 無業, 1 = 有業。ATUS の `telfs ∈ {1,2}` を有業に対応付け）

この $d$ の定義は `CVAE_Aggregate/japan_match_experiment.py` の `d_index` と**厳密に一致**させている。
ずれると、群別評価が別の群と突き合わされ、エラーも出ないまま結果だけが誤る。
そのため `smoke_test`（L702-704）に
「`cond_grid()` の行 $d$ が `cond_to_d` で $d$ に戻る」往復テストを入れてある。

### 4.2 条件の注入方法 — 属性別 Embedding の加算

```python
COND_SPEC = [("gender", 2, 4, ...), ("age", 7, 8, ...), ("telfs", 2, 4, ...)]
```

各属性を個別に `nn.Embedding` して連結（4+8+4 = 16 次元）→ `cond_proj` で 256 次元へ →
**timestep 埋め込みに足す**（`UNet1D.forward`, L329-330）:

```python
emb = self.time_mlp(timestep_embedding(t)) + self.embed_cond(cond_idx, ...)
```

**なぜ 28 通りの one-hot にしないのか**: 28 群のうち最小の群には、ATUS 平日で
**日記が 17 本しかない**（最大の群は 329 本）。群ごとに独立なパラメータを持たせると、
この 17 本だけから群固有の表現を学ぶことになる。
属性ごとに分解すれば、「女性である」効果を女性の全 14 群のデータで共有して学べる（統計的強度の共有）。

**なぜ足すのか（連結しないのか）**: 加算注入は、重みを共有した連結と等価な省パラメータ版であり、
拡散モデルの標準的な実装様式である（[[concepts/positional-encoding]] と同じ論法）。
`ResBlock1D` の各ブロックで `emb_proj(emb)` を特徴マップに足し込むので（L263）、
条件は UNet の全深さに繰り返し届く。

### 4.3 classifier-free guidance（CFG）

条件付き生成を「条件に**より**忠実」にする標準的な手法である。
仕組みは学習時とサンプリング時の 2 段構えになっている。

**学習時**（`Diffusion.loss`, L375）: 確率 `P_UNCOND = 0.1` で条件を捨て、
学習可能な `null_emb` に置き換える。これで 1 つのネットワークが
条件付き $\epsilon_\theta(x_t,t,c)$ と無条件 $\epsilon_\theta(x_t,t,\varnothing)$ の**両方**を学ぶ。

**サンプリング時**（`Diffusion._eps`, L379-386）: 2 つの予測を外挿する:

$$\hat\epsilon = \epsilon_\theta(x_t,t,\varnothing) + w \cdot \bigl(\epsilon_\theta(x_t,t,c) - \epsilon_\theta(x_t,t,\varnothing)\bigr)$$

- $w = 1$ で条件付き予測そのもの（コードは分岐で 1 回の前向き計算に短縮する）
- $w = 0$ で**無条件**生成。「$w=0$ が普通の条件付き生成」ではない
- $w > 1$ で条件の効果を増幅する。**代償として多様性が落ち、条件方向に過剰に振れる**

本コードは `GUIDANCE_SCALE = 1.25`。就業を条件に加えた結果、$w$ が WORK を強く増幅するようになったため、
`DDPM/model.py` の既定 2.0 から下げてある。根拠となる実測（ancestral, M=128）:

| CFG $w$ | 1.0 | **1.25** | 1.5 | 実 ATUS 平日 |
|---|---|---|---|---|
| WORK の時間シェア | 0.156 | **0.167** | 0.255 | 0.168 |
| 全活動のシェア誤差合計 $\sum\lvert\Delta\rvert$ | 0.061 | **0.044** | 0.174 | — |

$w=1.5$ で WORK が 1.5 倍に膨らむ。**「大きいほど条件に忠実で良い」ではない**という典型例である。

CFG の代償として、1 ステップあたりのネットワーク前向き計算が **2 回**になる
（条件付き + 無条件）。プール生成コストが 2 倍になるのはこのため。

## 5. denoiser（1D-UNet）の構造

$\epsilon_\theta$ の実体（`class UNet1D`, L281-341）。パラメータ数 **1,857,940**（約 186 万）。

### 5.1 部品

| 部品 | 中身 | 役割 |
|---|---|---|
| `timestep_embedding` | sinusoidal 位置符号（128 次元） | 「いまどれくらいノイズが乗っているか」をネットワークに伝える |
| `ResBlock1D` | GroupNorm → SiLU → Conv1d を 2 回 + 条件加算 + skip | 局所（隣接スロット）のパターン抽出 |
| `AttnBlock1D` | 時間軸の self-attention（4 ヘッド。48 / 24 解像度にのみ配置） | 遠距離依存（朝の出勤 ↔ 夕方の帰宅）の橋渡し |
| ダウン/アップサンプル | stride 2 の Conv1d / `interpolate` + Conv1d | 15 分粒度と 1 時間粒度の両方を見る |

**なぜ Conv1d か**: データは「96 スロットの時系列」であり、
隣接スロットにだけ局所相関がある 1 次元構造だからである。
画像用の 2D 畳み込みに合わせて無理に正方行列へ整形すると、
存在しない縦横の局所性を仮定してしまう（[[queries/ddpm-vs-other-diffusion]] の Kang vs Tang の対比）。

**UNet である理由**: 入出力が同じ形状 `(B,12,96)` の写像だからである。
skip 接続でスロット単位の細部を保ちつつ、深い層で全体構造を扱う。

### 5.2 形状の追跡表

`forward` を上から追うと（$B$ = バッチサイズ）:

| コード | 形状 | 備考 |
|---|---|---|
| `x_t` | (B, 12, 96) | 入力（活動 12 チャネル × 96 スロット） |
| `time_mlp(timestep_embedding(t))` | (B, 256) | 128 → 256 |
| `embed_cond(cond_idx)` | (B, 256) | 4+8+4=16 → 256 |
| `emb` = 上の 2 つの和 | (B, 256) | 全 ResBlock に配られる |
| `in_conv(x_t)` | (B, 64, 96) | |
| `h1 = d1b(d1a(...))` | (B, 64, 96) | skip 用に保持 |
| `ds1(h1)` | (B, 64, 48) | ↓ 30 分粒度 |
| `h2 = attn2(d2b(d2a(...)))` | (B, 128, 48) | skip 用に保持 |
| `ds2(h2)` | (B, 128, 24) | ↓ 1 時間粒度 |
| `h3 = attn3(d3b(d3a(...)))` | (B, 128, 24) | skip 用に保持 |
| `m = m2(m_attn(m1(h3)))` | (B, 128, 24) | ボトルネック |
| `u3(cat([m, h3]))` | (B, 128, 24) | 入力チャネルは 256 |
| `us2(interpolate(u, ×2))` | (B, 128, 48) | ↑ |
| `u2_attn(u2(cat([u, h2])))` | (B, 128, 48) | |
| `us1(interpolate(u, ×2))` | (B, 64, 96) | ↑ |
| `u1(cat([u, h1]))` | (B, 64, 96) | |
| `out_conv(silu(out_norm(u)))` | (B, 12, 96) | 予測ノイズ $\hat\epsilon$ |

**`out_conv` の重みをゼロ初期化している理由**（L314-317）:
学習開始時の出力を厳密に $\hat\epsilon = 0$ にすると、
$\hat{x}_0$ の復元式が $x_t / \sqrt{\bar\alpha_t}$ という素直な値から始まり、初期の発散を避けられる。
拡散モデルでは定石の初期化である。

## 6. 学習ループ

`train()`（L483-558）。通常の PyTorch 学習ループに、以下の 3 つの工夫が加わっているだけである。

### 6.1 調査ウェイトによる重み付きサンプリング

ATUS の個票には標本設計に由来する調査ウェイト `TUFINLWGT` が付いている。
これを無視すると米国人口を代表しない分布を学んでしまうため、
`WeightedRandomSampler` で**ウェイトに比例した確率で復元抽出**する（L222-225）。

- 1 エポックは「訓練データ件数と同じ回数の抽出」= 3,363 件 = 14 バッチ（`BATCH_SIZE=256`、最後は端数）
- 復元抽出なので、1 エポックの中に同じ日記が複数回入ることも、1 度も出ないこともある

### 6.2 EMA（指数移動平均）

```python
shadow ← decay · shadow + (1 - decay) · weights     # decay = 0.999、毎ステップ
```

学習中の重みは確率的勾配のノイズで振動する。その**時間平均**を別に保持しておくと、
生成品質が安定する（拡散モデルでは標準的な実務手法）。

- 平均化の実効的な時間窓は $1/(1-0.999) = 1000$ ステップ ≈ **71 エポック**（14 ステップ/エポック）
- `train()` は最後に `ema.copy_to(model)` するので、**返り値のモデルは EMA 重み**（L557）
- チェックポイントには raw と EMA の両方を保存し、`load_pretrained` は既定で EMA を読む

### 6.3 early stopping

検証 $\epsilon$-MSE が `EARLY_STOP_PATIENCE = 200` エポック改善しなければ打ち切り、
最良エポックの重みに戻す（L526-543）。

**注意すべき点**: 指標は $\epsilon$-MSE、つまり
「ランダムな $t$ とランダムなノイズに対する予測誤差の平均」である。
生成品質と単調に対応する量ではなく、エポック間の変化も小さい。
**生成が良いかどうかは必ず `sanity_check` の断片化統計で確認する**こと（→ [9.1](#91-まず個票が実データ水準かサニティチェック)）。

また、検証データは**調査ウェイトを掛けずに**評価している（`val_loader` は素の DataLoader、L228）。
訓練分布（ウェイト付き）と検証分布（非加重）は厳密には別物である。

## 7. サンプリング — ancestral と DDIM

### 7.1 DDIM とは

ancestral sampling は 1000 ステップすべてを辿るため遅い。
DDIM（Song et al. 2021）は $t$ の列を間引いて、例えば 50 ステップで生成する高速化手法である
（`Diffusion.ddim_sample`, L404-434）。

$$x_{t_{\text{prev}}} = \sqrt{\bar\alpha_{\text{prev}}}\,\hat{x}_0
\;+\; \underbrace{\sqrt{1-\bar\alpha_{\text{prev}}-\sigma^2}\,\hat\epsilon}_{\texttt{dir\_xt}}
\;+\; \sigma z,
\qquad \sigma = \eta\sqrt{\frac{1-\bar\alpha_{\text{prev}}}{1-\bar\alpha_t}\left(1-\frac{\bar\alpha_t}{\bar\alpha_{\text{prev}}}\right)}$$

$\eta$ が逆過程の確率性の強さを決める:

- $\eta = 0$: $\sigma = 0$ で**決定的**。$x_T$ を決めれば出力が一意に決まる（ODE を解くのと等価）
- $\eta = 1$: ancestral と同じ後方分散になり、確率的な逆過程に戻る

### 7.2 本コードでは DDIM を既定にしていない

`SAMPLER = 'ancestral'`（L143）。実測（M=128、実 ATUS 平日の平均切替 **12.64** と比較）:

| サンプラ | 平均切替回数 | 実データ比 |
|---|---|---|
| DDIM 50 ステップ, $\eta=0$ | 17.70 | 1.40 |
| DDIM 200 ステップ, $\eta=0$ | 22.57 | 1.79 |
| DDIM 50 ステップ, $\eta=1$ | 13.85 | 1.10 |
| DDIM 250 ステップ, $\eta=1$ | 17.73 | 1.40 |
| **ancestral 1000 ステップ** | **12.87** | **1.02** |

**直感に反する 2 点**:

1. **決定的 DDIM（$\eta=0$）でステップを増やすと悪化する**。
   近似誤差が原因ならステップを増やせば改善するはずで、逆行している
2. ancestral（1000 ステップ）が最良

原因は [3.3](#33-この表現の帰結重要) で述べた argmax デコードにある。
決定的 DDIM は条件付き平均へ収束するため、$\hat{x}_0$ が**ぼやける**。
ぼやけた 12 次元ベクトルでは argmax がスロットごとにちらつき、
「1 スロットだけの活動」が量産されて切替回数が増える。
ステップを増やすと ODE に忠実になる分、**ぼやけそのものがより正確に再現される**ため悪化する。
$\eta=1$ でノイズを戻せば改善するが、ancestral には届かない。

Route B の前提は「個票が実データ水準の系列品質を持つ」ことなので、
速度ではなく忠実度を採って ancestral を既定にしている。
プールの生成は npz にキャッシュされる一回限りのコストなので、この判断による不都合はない。

## 8. Stage 2 — 指数傾けによる集計マッチ

`japan_match_experiment.py` の中核。ここが本モデルの新規部分である。

### 8.1 なぜ勾配法が使えないのか

CVAE 版 Stage2 は「群別期待行動者率 $\hat\mu(d)$ を公表値に近づける」勾配降下だった。
これは $\hat\mu$ が**微分可能な閉形式**で書けたから成立していた。DDPM では 2 つの理由で成立しない:

1. **argmax デコードで勾配が切れる**。argmax はほとんど至るところ勾配 0 なので、逆伝播が通らない
2. **仮に通せても、1000 ステップ（CFG で前向き計算 2000 回）分の計算グラフを保持できない**

そこで **生成器を完全に凍結**し、$\hat\mu$ を「サンプルの重み付き平均」として扱って、
**重みだけ**を最適化する。凍結してしまえば、残るのは有限次元の凸問題である。

### 8.2 問題設定

**提案分布** $p_d$ = 凍結 DDPM の群 $d$ 条件付き分布。実体は $M = 2000$ 本のサンプル（プール）。

**特徴量** $\varphi(x)_{c,t} = \mathbb{1}(x_t = c)$。
この期待値 $\mathbb{E}_q[\varphi_{c,t}]$ が**そのまま時刻別行動者率**になる
（公表統計と同じ量が特徴量の期待値になるよう設計されている）。

**教師**は公表 2 表だけ（28 群のクロス表はホールドアウト評価用に取り分けてある）:

- `margin_ga`: 性 × 年齢 7 区分の時刻別行動者率（就業を周辺化した「総数」行）… **14 行**
- `margin_ge`: 性 × 就業の時刻別行動者率（年齢を周辺化した「総数」行）… **4 行**

**最適化問題**（最大エントロピー原理）:

$$\min_q \;\sum_d \mathrm{KL}(q_d \,\|\, p_d)
\quad \text{s.t.} \quad
\begin{cases}
\sum_e \pi(e \mid g,a)\, \mathbb{E}_{q_{(g,a,e)}}[\varphi] = \nu_{ga} & \text{(14 行)}\\[2pt]
\sum_a \pi(a \mid g,e)\, \mathbb{E}_{q_{(g,a,e)}}[\varphi] = \nu_{ge} & \text{(4 行)}
\end{cases}$$

式を言葉にすると **「公表集計に合う分布のうち、事前学習した米国分布から最も動かないものを選ぶ」**。
$\pi$ は社基調の推定人口から計算できる既知の人口シェアなので、制約は全確率の公式そのものである
（例: 「40 代男性の行動者率」= 有業割合 × 有業 40 代男性の率 + 無業割合 × 無業 40 代男性の率）。

なお目的関数は群ごとの KL の**単純和**である（人口重み付きではない）。
人口の小さい群も大きい群と同じだけ「米国分布から動くコスト」を払う設計になっている。

CVAE 版の「関数空間アンカー」は $\hat\mu$ から離れないようにする**追加の罰則項**だったが、
ここでは KL が目的関数そのものなので、アンカーが**最適化問題の定義に組み込まれている**。
調整すべきハイパーパラメータが 1 つ消えたことになる。

### 8.3 双対をゆっくり展開

制約付き最小化なので Lagrange 乗数 $\lambda_{ga}$（14 行分）と $\eta_{ge}$（4 行分）を導入する。
$q_d$ について変分をとると、最適解は**指数傾けの形**に決まる:

$$\boxed{\;q_d(x) \;\propto\; p_d(x)\,\exp\langle \theta_d, \varphi(x)\rangle,
\qquad \theta_{(g,a,e)} = \pi(e \mid g,a)\,\lambda_{ga} + \pi(a \mid g,e)\,\eta_{ge}\;}$$

**$\theta_d$ の構造がこの手法の要点**である。自由変数は 28 群分ではなく、
**公表された 18 行分の乗数だけ**である（要素数は $18 \times 11 \times 96 = 19{,}008$。
18 行 × OTHER_X 除外後の 11 活動 × 96 スロット）。群 $d$ の傾けは、
その群が属する 2 つの公表行の乗数を人口シェアで混ぜたものとして自動的に決まる。
未公表セルと比較不能活動 OTHER_X はマスクで落ちる（$\lambda, \eta$ を 0 に固定する）。

最大化すべき双対関数は:

$$g(\lambda,\eta) = -\sum_d \log \mathbb{E}_{p_d}\bigl[e^{\langle\theta_d,\varphi\rangle}\bigr]
+ \langle\lambda, \nu_{ga}\rangle + \langle\eta, \nu_{ge}\rangle$$

これは滑らかな**凹**関数なので、L-BFGS で大域最適に到達する（局所解が存在しない）。
勾配は

$$\frac{\partial g}{\partial \lambda_{ga}} = \nu_{ga} - \hat\mu_{ga}(\lambda,\eta)$$

すなわち **（教師 − 再構成周辺）**。最大化がそのまま「残差をゼロへ」という更新になる。

さらに、プールを固定した後の問題は**「$M$ 本の日記への重み配分を決める有限次元の凸問題」**
と厳密に一致する。連続分布を近似しているのではなく、離散版を厳密に解いている。

### 8.4 実装（`exponential_tilt`, L172-303）

| コード | 形状 | 意味 |
|---|---|---|
| `pool` → `idx` | (28, 2000, 96) | 提案サンプル（活動ラベルの整数） |
| `lam` | (2, 7, 12, 96) | $\lambda_{ga}$ = 性 × 年齢の乗数 |
| `eta` | (2, 2, 12, 96) | $\eta_{ge}$ = 性 × 就業の乗数 |
| `theta_of(...)` | (28, 12, 96) | $\theta_d$（$\pi$ で混ぜて 28 群に展開） |
| `scores_of(theta)` | (28, 2000) | $s_{dm} = \sum_t \theta_d[x_{dm}(t), t]$ |
| `w = softmax(s, dim=1)` | (28, 2000) | 群ごとに正規化された日記の重み |
| `mu` (`scatter_add_`) | (28, 12, 96) | 再構成した群別行動者率 $\hat\mu$ |
| `mu_ga` / `mu_ge` | (2,7,12,96) / (2,2,12,96) | $\pi$ で混合した周辺（教師と同じ形） |

読み方のコツ 3 点:

- **`theta[d_ar, idx, t_ar].sum(-1)`**: one-hot を作らず gather で内積を取っている。
  $\varphi$ が指示関数なので $\langle\theta,\varphi\rangle$ は
  「実際に取った活動に対応する $\theta$ を 96 個拾って足す」だけで済む
- **`logsumexp(s, dim=1) - log(M)`**: $\log \mathbb{E}_{p_d}[e^s]$ のモンテカルロ推定。
  `logsumexp` は $e^s$ のオーバーフローを防ぐための定石である
- **CPU / float64 に固定**（L192）: MPS が float64 に対応しておらず、
  float32 では L-BFGS が残差 $10^{-4}$ 前後で頭打ちになるため。
  要素数は $28 \times 2000 \times 96 \approx 5{\times}10^6$ と小さく、CPU でも数十秒で解ける

### 8.5 `RIDGE > 0` が必須である理由

$\lambda, \eta$ への L2 罰則 `ridge` は、**省略可能な正則化ではない**。

公表 2 表には**構造的な線形従属**がある。各 $(g, c, t)$ について

$$\sum_a \pi(a \mid g)\,\nu_{ga} \;=\; \sum_{a,e} \pi(a,e \mid g)\,\mu \;=\; \sum_e \pi(e \mid g)\,\nu_{ge}$$

が恒等的に成り立つ（どちらも「性 $g$ 全体の行動者率」を表すからである）。
つまり制約のうち $2 \times 11 \times 96 = 2{,}112$ 本が冗長である
（性別 2 通り × OTHER_X 除外後の 11 活動 × 96 スロット。
コードのコメントは除外前の 12 活動で数えて 2,304 本としている）。

冗長な制約があると、双対に**平坦方向**（動いても目的関数が変わらない方向）が残る。
その方向へ進むと、$q$ 自体は変わらないまま $\lambda$ だけが発散し、
数値的には softmax が飽和して**有効サンプル数（ESS）が枯れる**。

`ridge > 0` は (a) 双対を狭義凸にして最小ノルムの乗数を一意に選び、
(b) 有限プール $M$ でモーメントを厳密に追いすぎて $\theta$ が発散するのを防ぐ。

双対の $\frac{\text{ridge}}{2}\lVert\lambda\rVert^2$ は、主問題側では
**等式制約を係数 $1/(2\,\text{ridge})$ の二次罰則に緩めること**に対応する（Fenchel 双対）。
`ridge` を下げるほど「教師に厳密に合わせる」方向の要求が強くなる。

### 8.6 診断指標の読み方

`exponential_tilt` が返す `diag` の主要項目:

| 指標 | 定義 | 読み方 |
|---|---|---|
| `resid_mae` | 教師 18 行への残差の平均絶対値 | **学習した目的そのもの**。小さいほど良いが過適合しうる |
| `ess_median` | $\mathrm{ESS}_d = 1/\sum_m w_{dm}^2$ の中央値 | **実質何本の日記でその群を代表しているか**。1 に近づいたら破綻 |
| `kl_mean` | $\mathrm{KL}(q_d \Vert p_d) = \sum_m w_{dm}\log(M w_{dm})$ | 米国分布からどれだけ動いたか（nats） |
| `grad_norm` | 双対勾配のノルム | 収束したかの確認 |

**ESS の直感**: 重みが一様なら ESS = $M$ = 2000。1 本に集中すれば ESS = 1。
本命設定（ridge = 0.01）では ESS 中央値 115（5.8%）で、
「各群を実質 115 本の日記で代表している」という状態である。

**なぜ ESS を見るのか**: 残差だけを見ていると `ridge` を下げるほど改善するため、
際限なく下げたくなる。しかしホールドアウト評価は途中から悪化する（過適合）。
**ESS がその手前で警告を出す**（→ [9.5](#95-ridge-掃引--過適合の実測)）。

### 8.7 指数傾けの 2 つの限界

1. **プールの台の外には出られない**。$q_d \ll p_d$ なので、
   米国 DDPM が群 $d$ で一度も生成しないパターンは、どう重み付けしても作れない。
   日本固有の行動様式が米国プールに含まれていなければ、残差として残り、ESS の低下として現れる
2. **集団平均の系列統計は動く**。傾けは日記 1 本ごとの重み付けなので、
   **個票の中身は 1 スロットも変わらない**。ただし集団平均（例えば平均切替回数）は
   重みが変わる分だけ動く。断片化した日記に重みが寄れば集団平均は悪化しうる。
   そのため、傾けの前後で断片化統計を出力している（`main()` の最終ブロック、L391-403）

### 8.8 `test_tilting.py` — 双対の導出が正しいことの検証

凸双対の実装は「収束はするが別の問題を解いている」という失敗を起こしやすい。
下流の評価指標を見ても気づけないため、合成データで次の 4 点を検証している:

| テスト | 何を確かめるか | 実測（合成プール M=400） |
|---|---|---|
| 往復 | 既知の傾け $\theta^*$ が作る周辺を教師として与えたら、最適化後の周辺が一致するか | 残差 MAE $3.2\times10^{-7}$ |
| 恒等 | 教師 = 提案分布そのものなら一様重みが最適（$\theta = 0$, KL = 0）になるか | KL $6.0\times10^{-11}$ |
| ridge 単調性 | `ridge` を上げると傾けの強さ（KL）が単調に減るか | 0.131 → 0.114 → 0.090 → 0.049 |
| 正規化 | 重みが群ごとに和 1 になっているか | OK |

実行結果（`uv run python src/models/DDPM_Aggregate/test_tilting.py`）は `test_tilting: OK`。

### 9.1 まず個票が実データ水準か（サニティチェック）

Route B の前提は「DDPM の個票が実データ並みの系列品質を持つ」ことなので、
集計精度より先にこれを確認する（`fragmentation_stats` / `sanity_check`, L622-683）。

| 指標 | 意味 |
|---|---|
| `switches` | 1 日の活動切替回数（**断片化の主指標**） |
| `ep_len_mean` / `ep_len_median` | 1 エピソードの継続スロット数 |
| `single_slot_ratio` | 15 分 1 スロットで終わるエピソードの比率 |
| `participation` | 活動別の日次参加率（その日 1 度でもやった人の割合） |

CVAE が 3.8 倍（12.64 → 48.1）に断片化したのに対し、
DDPM は ancestral で 12.87（1.02 倍）を達成しており、これが生成器差し替えの根拠である。

**算出範囲が指標ごとに異なる点に注意**: `switches` と `participation` は
調査ウェイト付きで全行から計算するが、`ep_len_*` と `single_slot_ratio` は
先頭 3,000 行・非加重で計算する（→ [12 章 2 項](#12-コードを読むときの注意点)）。

### 9.2 教師とホールドアウトの分離

| | 使うもの |
|---|---|
| **学習（Stage2 の教師）** | 公表周辺 2 表（14 + 4 = 18 行） |
| **評価（ホールドアウト）** | 公表**群別**行動者率（28 群クロス表）— Stage2 で一切使わない |

これが「統計量ホールドアウト」デザインである。
教師に使った量が合うのは当然なので、**教師に入れていない群別クロス表で測る**。
`eval_against`（CVAE 版から import して出所を 1 つに保っている）の指標:

| 指標 | 定義 | 何を測るか |
|---|---|---|
| `rate_mae` | $\hat\mu(d)$ と公表 $\mu^*(d)$ の平均絶対誤差 | 総合誤差。解釈しやすい主指標 |
| `rate_rmse` | 同 RMSE | 誤差上位セル（WORK 昼・SLEEP 深夜のピーク帯）への敏感さ |
| `dev_mae` / `dev_rmse` | 群偏差 $\mu(d) - $ 人口平均 の部分だけの誤差 | **条件付け能力の主指標** |

`dev_*` を分けて見る理由: 全群に日本の人口平均を返すだけの `baseline` でも `rate_*` はある程度下がる。
「群ごとの違いを当てられているか」は偏差成分でしか測れない。

### 9.3 比較条件（バリアント）

| バリアント | 何をするか | 何のための対照か |
|---|---|---|
| `zero-shot` | 傾けなし（一様重み） | 米国 DDPM の構造持ち込みだけでどこまで合うか |
| `tilted` | 指数傾け | **本命** |
| `shuffled` | 群対応をシャッフルしたプールに傾ける | **負の対照**。「正しい群対応だから効く」ことの反証条件 |
| `baseline` | 全群 = 日本の人口平均 | モデル不要の床 |

主張が通る条件は 2 つある: **`tilted` が `zero-shot` と `baseline` の両方を下回ること**、
および **`shuffled` ではその改善が消えること**。前者だけでは
「たまたま日本の平均に近づいた」可能性を排除できない。

### 9.4 実測結果（2026-07-29 実行, M = 2000, `--ridge-sweep --ridge 1e-4`）

`data/processed/aggregates/ddpm_japan_match_experiment.csv` より（値が小さいほど良い）:

| variant | rate_mae | rate_rmse | dev_mae | **dev_rmse** |
|---|---|---|---|---|
| zero-shot | 0.0289 | 0.0571 | 0.0227 | 0.0425 |
| **tilted (ridge=0.01)** | **0.0113** | **0.0216** | **0.0109** | **0.0208** |
| tilted (ridge=1e-3) | 0.0127 | 0.0254 | 0.0127 | 0.0254 |
| tilted (ridge=1e-4) | 0.0134 | 0.0276 | 0.0134 | 0.0276 |
| tilted (ridge=1e-5) | 0.0257 | 0.0541 | 0.0266 | 0.0539 |
| tilted (ridge=0) | 0.0881 | 0.2082 | 0.0920 | 0.2063 |
| shuffled (ridge=1e-4) | 0.0364 | 0.0898 | 0.0378 | 0.0907 |
| baseline | 0.0390 | 0.0861 | 0.0390 | 0.0861 |

読み取れること:

1. **zero-shot（0.0425）が baseline（0.0861）を大きく下回る** →
   米国 DDPM の群差構造は、傾けなしでも日本の群差をある程度説明する
2. **tilted（0.0208）は zero-shot の半分以下** → 公表 2 表による傾けが効いている
3. **shuffled（0.0907）では改善が完全に消え、baseline（0.0861）より悪くなる**
   （同じ ridge = 1e-4 の tilted は 0.0276）→ 負の対照が期待どおり機能している。
   「群対応が正しいこと」が効果の源泉である
4. **ridge = 0 では破綻する（0.2063）** →
   [8.5](#85-ridge--0-が必須である理由)で述べた識別性の問題が実際に現れる

### 9.5 ridge 掃引 — 過適合の実測

`ddpm_japan_match_tilting.csv`（教師への残差）と上表（ホールドアウト）を並べる:

| ridge | 教師残差 `resid_mae` ↓ | ESS 中央値 | ホールドアウト `dev_rmse` |
|---|---|---|---|
| 0.01 | 0.00473 | **115 (5.8%)** | **0.0208** |
| 1e-3 | 0.00421 | 67 (3.4%) | 0.0254 |
| 1e-4 | 0.00420 | 62 (3.1%) | 0.0276 |
| 1e-5 | 0.01495 | 22 (1.1%) | 0.0539 |
| 0 | 0.06828 | **1 (0.05%)** | 0.2063 |

**教師残差はほぼ横ばい（0.0047 → 0.0042）にもかかわらず、
ホールドアウトは 33% 悪化している**（0.0208 → 0.0276）。
これが「教師周辺への過適合」である。ESS は 115 → 62 とほぼ半減しており、
ホールドアウト評価より先に警告を出している。
`ridge = 0` では ESS = 1、つまり各群で 1 本の日記が全重みを持つ状態になるため、
$\hat\mu$ が 0/1 の指示関数に縮退し、教師残差まで悪化する。

**実務的な読み方**: ESS 中央値が本命設定の 5.8%（115/2000）を大きく下回り 3% 台以下になったら、
傾けが強すぎると判断して `ridge` を上げる。

### 10.3 計算コストの見積り

学習は軽い（N = 3,736、186 万パラメータ、14 ステップ/エポック）。**重いのはプール生成**である。

- サンプル数: 28 群 × 2,000 本 = **56,000 本**
- `GEN_BATCH = 1024` なので **55 バッチ**
- 1 バッチあたりのネットワーク前向き計算: 1000 ステップ × 2（CFG の条件付き + 無条件）= **2,000 回**
- 合計 **約 11 万回**の前向き計算

DDIM 50 ステップなら 1 バッチ 100 回に減り **20 倍速い**が、
[7.2](#72-本コードでは-ddim-を既定にしていない)の品質低下と引き換えになる。
プールの生成は npz にキャッシュされる一回限りのコストなので、
反復実験では `--reuse-pool` を使う。

Stage2 の傾け自体は CPU float64 で数十秒である。

## 11. よくある勘違い

拡散モデル一般と、このコード特有のものを分けて並べる。

### 拡散モデル一般

| 勘違い | 実際 |
|---|---|
| 学習では $t$ を 1 → 1000 と順に増やしていく | サンプルごとに $t$ を**一様ランダムに 1 個**引くだけ（L372）。順番は不要 |
| ネットワークはノイズを引き算して $x_0$ を出す | 出すのは**乗っているノイズ $\hat\epsilon$**。$x_0$ は式で復元する（等価な言い換え） |
| ステップを増やせば必ず良くなる | 決定的 DDIM では**増やすほど悪化**する（[7.2](#72-本コードでは-ddim-を既定にしていない)）。ぼやけが忠実に再現されるため |
| CFG は大きいほど条件に忠実で良い | $w = 1.5$ で WORK シェアが実測の 1.5 倍に膨らむ（[4.3](#43-classifier-free-guidancecfg)）。既定は 1.25 |
| CFG の $w=0$ が普通の条件付き生成 | $w=0$ は**無条件**生成。条件付きそのものは $w=1$ |
| DDIM は速いので常に使うべき | argmax デコードする離散拡散では品質が落ちる。既定は ancestral |
| 検証損失が下がらない = 学習失敗 | $\epsilon$-MSE はランダムな $t$ と $\epsilon$ にわたる平均なので変化が小さい。生成品質は断片化統計で判定する |
| 出力は $\{-1,+1\}$ になるはず | 出力は連続値。ラベルは argmax で読む。絶対値の大小に意味はない |

### このコード特有

| 勘違い | 実際 |
|---|---|
| Stage2 はモデルの fine-tune | 生成器は**完全に凍結**。最適化するのは日記 1 本ごとの重みだけ（[8.1](#81-なぜ勾配法が使えないのか)） |
| 指数傾けは個票を書き換える | 個票は 1 スロットも変わらない。変わるのは混ぜ方だけ。ただし**集団平均の統計は動く**（[8.7](#87-指数傾けの-2-つの限界)） |
| `ridge` は省略できる正則化 | 公表 2 表の線形従属で双対に平坦方向が残るため**必須**。0 では ESS = 1 まで落ちる（[8.5](#85-ridge--0-が必須である理由)） |
| 残差が小さければ小さいほど良い | 残差が横ばいのままホールドアウトが 33% 悪化する領域がある（[9.5](#95-ridge-掃引--過適合の実測)） |
| OTHER_X は生成しない | 生成される（96 スロット全てにラベルが必要）。制約と評価から外すだけ |
| 傾けは 28 群分のパラメータを持つ | 自由変数は**公表 18 行分**の $\lambda, \eta$。群の傾けは $\pi$ で混ぜて決まる（[8.3](#83-双対をゆっくり展開)） |
| 28 群を one-hot 条件にすればよい | 最小の群には日記が 17 本しかない。属性ごとの Embedding で統計的強度を共有する（[4.2](#42-条件の注入方法--属性別-embedding-の加算)） |
| 傾ければ日本の分布に到達できる | プールの台の外には出られない。米国 DDPM が生成しないパターンは作れない（[8.7](#87-指数傾けの-2-つの限界)） |
| 学習後の `model` は最終エポックの重み | `train()` は最後に EMA をコピーする。`load_pretrained` も既定で EMA（[6.2](#62-ema指数移動平均)） |

## 12. コードを読むときの注意点

コードとコメント・出力の間にある食い違いや、解釈を誤りやすい箇所を挙げる。
**バグ報告ではなく読解上の注意**である。

1. **`EPOCHS = 1000` だが、コメントには 3000 と書かれている**（L117-119）。
   実際に効くのは定数側の 1000 である。ただし `EARLY_STOP_PATIENCE = 200` が先に効くことも多いため、
   実際の停止エポックは実行ログで確認する
2. **`fragmentation_stats` のエピソード系指標は先頭 3,000 行・非加重**（L631）。
   `switches` と `participation` はウェイト付きで全行を使うが、
   `ep_len_*` と `single_slot_ratio` は `sched[:3000]` のループでウェイトを使わない。
   プール（56,000 行）に対して使うと、**先頭 2 群分（$d=0,1$: 男性 15–24 歳）しか見ていない**ことになる。
   このため `japan_match_experiment` の出力では
   「1 スロット ep 比率」が zero-shot と tilted で同じ値になる。傾けの効果を見る指標として読まないこと
3. **プールの npz にサンプラ種別が記録されない**（L164 で `pool` 配列だけ保存）。
   `--reuse-pool` で読み込んだプールが ancestral 由来か DDIM 由来かはファイルから判別できない。
   サンプラを変えて比較するときは npz を退避するか作り直す
4. **`--ridge-sweep` 時の `shuffled` は `--ridge` の値を使う**（L360）。
   掃引で最良だった ridge ではないため、
   負の対照として読むときは**同じ ridge の `tilted` 行と比べる**こと
5. **`pool_to_rates` は渡された重みを再度正規化する**（L614）。
   `exponential_tilt` の出力は既に softmax で正規化済みなので二重だが、無害である
6. **モジュールの明示ロード**（L100-113）。`CVAE_Aggregate` と `DDPM_Aggregate` は
   同名ファイル（`model.py` / `japan_match_experiment.py`）を持つため、
   通常の `import` では `sys.path` の順序次第で、気付かないうちに別モデルを読み込んでしまう。
   `importlib` で一意な名前を付けて `sys.modules` に載せているのは、その回避策である。
   `jm` = CVAE 版（教師読込・評価の唯一の出所）、`ddpm` = 本ディレクトリの `model.py`
7. **スコープは平日のみ**（`DAY_FILTER = 'weekday'`, `day_of_week` 2–6）。
   土日への拡張は、曜日タイプを条件に加える将来課題として残っている。
   数値を CVAE 版と比較するときは、スコープが揃っているか確認する
